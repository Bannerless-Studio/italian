# tools/ — builder inputs (dev/agent notes)

Purpose: everything the Italian pack build reads or writes, other than the
shared builder itself (`engine/tools/packbuilder`, `langs/it.py`). Read this
before touching any file here; it says what is hand-maintained vs generated.

## Files

- `build_pack.py` — shim. Runs `python3 -m packbuilder build --lang it --repo .`
  against `engine/tools` (or `$PACKBUILDER_PATH`). Hand-maintained, rarely changes.
- `requirements.txt` — hand-maintained. packbuilder's requirements plus the
  Italian spaCy model (`it_core_news_sm`).
- `gloss_overrides.json` — hand-maintained. ~23 hand gloss fixes for
  high-frequency words the sense-ranking gets wrong (stare, piacere, ci/le/gli/lo...).
- `forced_a1.txt` — hand-maintained. A1 core word list forced into A1 (closed
  sets like days/months/numbers live in `langs/it.py` instead).
- `passages_src.json` — hand-maintained. Source text for the 60 reading
  passages; `packbuilder passages` builds `pack/passages.json` from it.
- `generated_examples.tsv` — hand-reviewed written example sentences (`"src":
  "gen"` in sentences.json), exempt from the drop-everywhere content filter.
  Used to refill a word left without an example after a content-policy removal
  (e.g. il suicidio).
- `id_map_v1.json` — generated, then frozen. Maps (lemma, POS) to a fixed
  word id across rebuilds. Never hand-edit; never renumber.
- `REPORT.md` — generated on every full build by `build_pack.py`. Everything
  outside the `manual` markers is regenerated; the manual section (QA
  verdicts, check output) is preserved across runs.
- `REPORT_passages.md` — generated by `packbuilder passages`. Per-passage
  coverage numbers and QA notes.
- `__pycache__/` — generated, gitignored.

## Rebuild

See CLAUDE.md's "Commands" section for the pinned invocations. Sources
download once into `.cache/` (gitignored) and are reused; the build is
deterministic, so a cached re-run reproduces byte-identical `pack/*.json`.
`build_pack.py --stage {corpus,tag,lex,freq,words,all}` runs a single stage
from cached intermediate output in `.cache/derived/`.

## How words, senses and links are chosen (v2)

Part of speech, lemma and sense come from corpus usage, not dictionary
structure:

1. Tatoeba Italian sentences with an English translation are POS-tagged with
   spaCy `it_core_news_sm`. Each token's lemma is validated against
   Wiktionary inflection data (`vado` -> andare, `detto` -> dire, `sulla` ->
   su, `farlo`/`dimmi` -> fare/dire).
2. Each subtitle/wordfreq surface form's count is split over the (lemma, POS)
   pairs it takes in context, so `sei` counts for both essere and "six".
3. The Wiktionary entry is the one whose POS matches the corpus POS; filters
   (proper noun, misspelling, form-of, feminine-of) run on that entry only.
4. Senses are ranked by overlap with the English translations of sentences
   using the word, archaic/regional/rare senses last. A word whose main gloss
   already leads a higher-ranked word of the same POS leads with its next
   sense instead. `gloss_overrides.json` fixes 23 high-frequency glosses the
   ranking gets wrong (stare, piacere, ci/le/gli/lo...).
5. A lemma gets a second entry when another POS holds at least 20% of its
   corpus tokens with a distinct sense (la cosa "thing" and cosa "what?").
   Reflexive-clitic verbs show as -rsi (lamentarsi); feminine nouns meaning
   the same as an in-pack masculine (l'amica) fold into it as an `alt`.
6. Sentence word links are made per token in context (a clitic `la` never
   links the article; a noun links only when the article's gender agrees).
7. Closed sets (days, months, numbers, colours, greetings) and the A1 core
   list (`forced_a1.txt`) are forced into A1; everything else is levelled by
   frequency rank.

The generic algorithm (level bands, stages, how to add a language) is in
`engine/tools/packbuilder/README.md`.

## Reading passages

`packbuilder passages .` builds `pack/passages.json` from `passages_src.json`
and writes `REPORT_passages.md`. It links word ids the same way as Tatoeba
sentences, and enforces in-pack coverage of at least 95% at A1/A2 and 93% at
B1, plus a level budget (an A1 passage may use at most 3 A2 words, an A2
passage at most 3 B1 words). Regenerate `pack/*.js` afterward (jsonify_pack.py
appends passages into sentences.js).
